# W09-B — Serve the authenticated app-scoped snapshot

## Objective

Implement the bounded, cursor-stable, app-scoped onboarding snapshot for a registered workload.

## Authority and inputs

- [W-9 requirements](../../../work-items.md#w-9--relay-onboarding-and-expose-the-repair-snapshot)
- [Snapshot OpenAPI](../../../../contracts/http/iam-onboarding-snapshot.openapi.yaml)
- [Response schema](../../../../contracts/http/onboarding-snapshot-response.schema.json)
- [D-11](../../../artifacts/implementation-decision-log.md)

## Outputs and ownership

Own the snapshot query, its HTTP controller, the V12 migration function, and focused tests. Do not implement workload credential provisioning.

## Acceptance

- Only ACTIVE activations for the path app are returned; items are exactly the allowlisted fields.
- Cursor is opaque, stable under inserts, and page size is bounded by the contract.
- Path app must equal the authenticated workload binding; mismatch, missing scope/audience and unknown app all return the same non-enumerating 404.
- No global identity, identifier, credential or token appears in responses, errors, logs or metrics.
