# W07-E — Compose rollback-safe token issuance

## Objective

Compose the reviewed proof, state, deadline, and boundary ports into one rollback-safe authorization-code token issuance transaction.

## Dependencies and inputs

Requires reviewed W07-A, W07-B, W07-C, and W07-D. Inputs are their settled interfaces plus W-4 code redemption, W-5 subject/current-security authority, and W-6 signing.

## Outputs and ownership

Produce the production orchestration and dependency wiring consumed by W07-I. Own only declared orchestrator/configuration paths.

## Acceptance

- Initial valid proof produces a nonce challenge without inspecting or consuming the authorization code.
- Challenge rate limiting runs before proof verification, database and signing work; retry rate limiting runs after proof verification but before the issuance transaction, using the reviewed W07-D request context.
- Retry atomically consumes authorization code and nonce, claims replay across digest aliases, resolves current subject/security state, signs within the deadline, and writes PII-free issuance audit.
- Any failure at every seam rolls back all local database state.
- Concurrent/cross-instance retry has one winner.
- Identity disablement or registration drift overlapping issuance waits/revalidates safely under documented lock order.
- Commit failure and response loss do not produce a second usable code or proof.
- No refresh, bearer, OIDC, session, activation, or debug path is introduced.

## Scope amendment (2026-10-30)

Recorded scope decision after reviews 01–03: rollback at the code-consumption, subject-resolution, audit and commit
seams, concurrent/cross-instance retry-winner proof, concurrent disablement/registration-drift overlap, and
commit-failure/response-loss behaviour are owned by W07-I, which owns the full HTTP/transaction scenario. W07-E proves nonce and replay rollback, signer-timeout rollback, limiter ordering, and the retention invariant.
Concurrent TOKEN-purpose consumption is exercised only indirectly here (single-statement consume plus the resource-claim
race test); W07-I owns the dedicated concurrent/cross-instance retry-winner scenario. This amendment supersedes the corresponding acceptance bullets above.
