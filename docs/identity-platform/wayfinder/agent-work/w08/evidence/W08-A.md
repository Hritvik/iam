## What was built

- `V10__app_activation.sql`: `app_activation` with one row per `(app, identity)`, FK to the resolved
  `app_subject`, state/version/onboarding coherence constraint, and three `SECURITY DEFINER`
  functions (`evaluate_activation_prerequisites`, `read_activation_evidence`,
  `advance_app_activation`, `read_app_activation`) plus least-privilege grants.
- Java: `ActivationState`, `ActivationEvidence`, `ActivationPrerequisites`,
  `ActivationPrerequisiteEvaluator`, `AppActivation`, `ActivationCommand`, `ActivationTransition`,
  `AppActivationRepository`, `AppActivationService`, `JdbcAppActivationRepository`, secure activation
  id generator.
- Activation is decided from the app's registered `policy_activation_evidence` set plus the presence
  of the app subject; a missing item yields `PENDING_PREREQUISITES` with `onboarding_version = 0`.
