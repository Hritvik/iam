# W08-A — Evaluate prerequisites and persist strict activation

## Objective

Decide `PENDING_PREREQUISITES` or `ACTIVE` from the complete registered prerequisite set and persist the transition with expected-version writes.

## Authority and inputs

- [W-8 requirements](../../../work-items.md#w-8--activate-dutch-and-append-one-onboarding-intent)
- [Activation model](../../../feature-implementation-plan.md#app-subject-and-activation-model)
- [D-10](../../../artifacts/implementation-decision-log.md)
- Existing `app_subject`, `human_identity`, verified-identifier and factor/recovery evidence tables.

## Outputs and ownership

Own the activation state machine, its repository, the V10 migration and focused tests. Do not write outbox rows or compose the first-activation transaction.

## Acceptance

- Missing verified identifier, usable factor, recovery path, or registered app prerequisite yields `PENDING_PREREQUISITES` and no side effect.
- `ACTIVE` is reachable only when the whole set is satisfied.
- Writes use expected activation version and are idempotent under retry and concurrency.
- Only `PENDING_PREREQUISITES -> ACTIVE` is exercised; other states are constrained but unused.
- One activation row per `(app_registration_id, human_identity_id)`; the row references the stable App Subject.

## Verification

RED: a missing-evidence identity is persisted as ACTIVE or loses a prerequisite check.

```bash
./gradlew test --tests '*ActivationPrerequisiteEvaluatorTest' --tests '*AppActivationServiceTest'
./gradlew integrationTest --tests '*AppActivationPersistenceIntegrationTest'
```

- Current state: ready.
- Next action: claim, reproduce a missing-prerequisite activation, then encode the closed evaluator.
